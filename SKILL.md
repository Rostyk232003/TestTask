## 1. Архітектурні та Кодові Стандарти

* **Архітектура:** Clean Architecture з подібним розбиттям шарів:
  * `Domain`: Сутності (`Hall`, `Booking`, `Service`, `HallService`), Value Objects, Domain Events.
  * `Application`: CQRS Команди/Запити (`MediatR`), DTO, `FluentValidation`, `IPricingStrategy`.
  * `Infrastructure`: `AppDbContext` (`EF Core` + `SQLite`), Fluent API конфігурації, міграції, репозиторії.
  * `API`: REST Контролери, Global Exception Handling Middleware, Swagger/OpenAPI.
* **База даних:** `SQLite` через `Entity Framework Core`. Жодного чистого JSON-збереження для бізнес-даних.
* **Helpers-гігієна:** Усі `const` (магічні числа, коефіцієнти знижок), `readonly` параметри, методи `IsValid` та допоміжні статичні класи ПОВИННІ виноситися у папку `Helpers/` (наприклад, `Helpers/PricingConstants.cs`). Основні класи не повинні містити хардкоду.
* **Строга типізація:** **ЗАБОРОНЕНО** використовувати `var` у згенерованому коді (виняток — анонімні проекції LINQ). Завжди явно вказуйте типи (наприклад, `List<Hall> availableHalls = new List<Hall>();`).

## 2. Робочий Процес (Workflow) та ToT-Протокол

Перед створенням або зміною будь-якого коду обов'язково виконується 5 кроків:

1. **Крок 1 (Major vX.0 — ToT Генерація):** Запропонувати 2–3 концептуальних підходи (V1, V2, V3) із порівняльним аналізом (Плюси / Мінуси / Складність).
2. **Крок 2 (Draft History):** Надати чернетку запису, яка буде додана до файлу історії промптів.
3. **Крок 3 (User Approval):** Очікувати явного вибору варіанту та підтвердження користувачем команди **"Виконуємо"**.
4. **Крок 4 (Coding):** Написати код із обов'язковими інлайновими мітками `// PROMPT vX.Y.Z`.
5. **Крок 5 (Finalization):** Записати підсумковий промпт у файл історії та надати список змінених файлів.

## 3. Версіонування та Журналізація (`prompt_history`)

* **Мажорні версії (`v1.0`, `v2.0`):** Нові фічі. Кожна фіча має СВІЙ файл у папці `prompt_history/` (наприклад, `prompt_history/PROMPT_HISTORY_v1.0_PricingEngine.md`).
* **Мінорні версії (`v1.1`, `v1.2`):** Ітерації та покращення в межах фічі.
* **Патчі (`v1.1.1`):** Локальні виправлення багів.
* **Статуси у журналі:** `[Активна]` — реалізований код, `[Архів]` — відхилена або застаріла гілка ToT.
